۱. SQL چه کاربردی دارد؟

SQL ابزاری برای پرسیدن سؤال از داده‌های ذخیره‌شده در پایگاه داده است. با نوشتن یک پرس‌وجو یا Query مشخص می‌کنیم چه اطلاعاتی را می‌خواهیم و این اطلاعات از کدام جدول یا جدول‌ها باید دریافت شوند.

پرس‌وجوها می‌توانند برای پاسخ‌دادن به سؤال‌هایی درباره یک جدول یا چند جدول مرتبط استفاده شوند. برای نمونه، در پایگاه داده کتابخانه می‌توانیم مشخص کنیم جیمز در سال ۲۰۲۲ چه کتاب‌هایی را امانت گرفته است. در یک پایگاه داده منابع انسانی نیز می‌توان حقوق کارکنان واحدهای بازاریابی و حسابداری را استخراج کرد و آن‌ها را با یکدیگر مقایسه کرد.

چگونه می‌توان از حجم زیادی از داده‌های مرتبط، روندها و الگوها را استخراج کرد؟

SQL در بسیاری از سازمان‌ها در کنار ابزارهایی مانند نرم‌افزارهای صفحه‌گسترده استفاده می‌شود. مزیت مهم آن، امکان پرس‌وجو از حجم زیادی از داده‌ها و بررسی ارتباط میان بخش‌های مختلف اطلاعات است.

اگر اطلاعات موردنیاز در چند جدول مرتبط و در حجم زیاد نگهداری می‌شود، SQL می‌تواند راه مناسبی برای استخراج و تحلیل آن باشد. اگر تمام اطلاعات لازم در یک صفحه‌گسترده ساده و بدون ارتباط‌های پیچیده وجود داشته باشد، ممکن است استفاده از همان ابزار کافی باشد.

۲. ساختار اولین پرس‌وجوی SQL

واژه‌های کلیدی (Keywords)

واژه‌های کلیدی، کلمات رزروشده‌ای هستند که نوع عملیاتی را که SQL باید انجام دهد مشخص می‌کنند. دو واژه کلیدی پایه که برای نوشتن اولین پرس‌وجو به آن‌ها نیاز داریم عبارت‌اند از:

SELECT

مشخص می‌کند کدام فیلدها یا ستون‌ها باید در خروجی نمایش داده شوند.

FROM

مشخص می‌کند اطلاعات موردنظر از کدام جدول دریافت شوند.

فرض کنیم می‌خواهیم نام تمام اعضای کتابخانه را از جدول patrons دریافت کنیم. ستون موردنیاز name است و نام جدول نیز patrons است.

SELECT name
FROM patrons;

در این دستور، ابتدا ستون name با SELECT انتخاب شده و سپس با FROM مشخص شده است که این ستون از جدول patrons خوانده شود.

۱. انتخاب ستون

SELECT name

۲. تعیین جدول

FROM patrons

۳. پایان دستور

افزودن ;

نقطه‌ویرگول و شیوه نوشتن

نقطه‌ویرگول ; پایان دستور SQL را مشخص می‌کند. در سبک نگارشی رایج، واژه‌های کلیدی مانند SELECT و FROM با حروف بزرگ نوشته می‌شوند؛ در مقابل، نام جدول‌ها و فیلدها با حروف کوچک نوشته می‌شوند. این شیوه باعث می‌شود خواندن و بررسی پرس‌وجوها آسان‌تر شود.

خروجی اجرای پرس‌وجو، مجموعه‌ای از ردیف‌ها و ستون‌هاست که به آن Result Set می‌گویند. در مثال بالا، مجموعه نتایج شامل نام اعضای جدول patrons خواهد بود.

۳. انتخاب چند ستون یا تمام ستون‌ها

انتخاب چند فیلد

اگر به بیش از یک ستون نیاز داشته باشیم، نام ستون‌ها را پس از SELECT می‌نویسیم و آن‌ها را با کاما از یکدیگر جدا می‌کنیم. ترتیب نوشتن نام ستون‌ها، ترتیب نمایش آن‌ها در مجموعه نتایج را تعیین می‌کند.

برای مثال، برای مشاهده شماره عضویت و نام اعضا:

SELECT card_num, name
FROM patrons;

همچنین می‌توانیم سه ستون name، card_num و total_fine را به همین روش انتخاب کنیم:

SELECT name, card_num, total_fine
FROM patrons;

انتخاب تمام ستون‌ها با ستاره

برای انتخاب تمام ستون‌های یک جدول، لازم نیست نام تک‌تک آن‌ها را بنویسیم. می‌توانیم از علامت ستاره * استفاده کنیم. این علامت در این کاربرد، نویسه عمومی یا Wildcard است و به معنی انتخاب همه ستون‌هاست.

SELECT *
FROM patrons;

علامت * تمام ستون‌های جدول را انتخاب می‌کند؛ اما اگر فقط به چند ستون مشخص نیاز دارید، بهتر است نام همان ستون‌ها را بنویسید تا خروجی دقیق‌تر و خواناتر باشد.

۴. تمرین عملی: پرس‌وجو از جدول books

در این تمرین با استفاده از جدول books سه حالت مختلف انتخاب ستون را اجرا می‌کنیم. هدف، تمرین نوشتن SELECT و FROM است.

تمرین اول

فقط ستون title را انتخاب کنید تا عنوان همه کتاب‌ها نمایش داده شود.

تمرین دوم

ستون‌های title و author را با هم انتخاب کنید.

تمرین سوم

تمام ستون‌های جدول books را نمایش دهید.

پاسخ تمرین اول: انتخاب عنوان کتاب‌ها

SELECT title
FROM books;

پاسخ تمرین دوم: انتخاب عنوان و نویسنده

SELECT title, author
FROM books;

پاسخ تمرین سوم: انتخاب تمام ستون‌ها

SELECT *
FROM books;

در هر سه پرس‌وجو، جدول منبع یکسان است؛ تفاوت فقط در ستون‌هایی است که پس از SELECT انتخاب می‌کنیم.

۵. خواناتر کردن خروجی: نام مستعار و DISTINCT

نام مستعار ستون‌ها (Aliasing)

گاهی نام اصلی یک ستون برای نمایش در نتیجه پرس‌وجو به‌اندازه کافی روشن یا کوتاه نیست. در این حالت می‌توانیم با استفاده از واژه کلیدی AS برای ستون یک نام مستعار یا Alias تعیین کنیم.

فرض کنید جدول employees ستونی به نام name دارد که فقط نام کوچک کارکنان را نگهداری می‌کند. می‌توانیم نام این ستون را در خروجی به first_name تغییر دهیم:

SELECT name AS first_name
FROM employees;

نام مستعار فقط نام ستون را در مجموعه نتایج تغییر می‌دهد. نام واقعی فیلد در جدول همچنان name باقی می‌ماند و ساختار جدول تغییر نمی‌کند.

حذف مقادیر تکراری با DISTINCT

گاهی می‌خواهیم فهرستی از مقادیر یکتا داشته باشیم؛ یعنی هر مقدار فقط یک‌بار در خروجی دیده شود. برای این کار از واژه کلیدی DISTINCT استفاده می‌کنیم.

برای مثال، اگر ستون year_hired را از جدول کارکنان انتخاب کنیم، ممکن است سال استخدام بعضی کارکنان چند بار در خروجی تکرار شود. با قرار دادن DISTINCT پیش از نام ستون، سال‌های تکراری حذف می‌شوند:

SELECT DISTINCT year_hired
FROM employees;

اگر این دستور اجرا شود، هر سال استخدام فقط یک‌بار در مجموعه نتایج ظاهر می‌شود؛ حتی اگر چند کارمند در همان سال استخدام شده باشند.

DISTINCT برای چند ستون

می‌توانیم پس از DISTINCT چند ستون بنویسیم. در این حالت، SQL ترکیب یکتای مقادیر آن ستون‌ها را برمی‌گرداند. برای نمونه، اگر بخواهیم ترکیب واحد سازمانی و سال استخدام را بررسی کنیم، هر ترکیب از dept_id و year_hired فقط یک‌بار در خروجی ظاهر می‌شود.

SELECT DISTINCT dept_id, year_hired
FROM employees;

DISTINCT در حالت چندستونی، یکتاییِ ترکیب کامل ستون‌های انتخاب‌شده را بررسی می‌کند؛ نه اینکه مقادیر هر ستون را به‌طور مستقل و جداگانه یکتا کند. بنابراین ممکن است یک dept_id یا یک year_hired به‌تنهایی چند بار دیده شود، اما هیچ دو ردیفی ترکیب کاملاً یکسانی نداشته باشند.

تمرین: نویسندگان و ژانرهای یکتا

جدول books شامل ۳۵۰ کتاب است. ابتدا فقط نویسندگان یکتا را انتخاب کنید. سپس پرس‌وجو را طوری تغییر دهید که ترکیب‌های یکتای نویسنده و ژانر نمایش داده شوند.

SELECT DISTINCT author
FROM books;

برای دریافت ترکیب یکتای نویسنده و ژانر، هر دو فیلد را پس از DISTINCT قرار می‌دهیم:

SELECT DISTINCT author, genre
FROM books;

تمرین: تغییر نام ستون خروجی

در پرس‌وجوی زیر، نام ستون author را در خروجی به unique_author تغییر می‌دهیم:

SELECT DISTINCT author AS unique_author
FROM books;

۶. ذخیره پرس‌وجوها با View

گاهی یک پرس‌وجو را با دقت طراحی کرده‌ایم و می‌خواهیم بعداً دوباره از آن استفاده کنیم یا امکان استفاده از آن را برای دیگران فراهم کنیم. در این شرایط می‌توانیم پرس‌وجو را به شکل یک View ذخیره کنیم.

View چیست؟

View یک پرس‌وجوی SQL ذخیره‌شده است که هنگام استفاده، مانند یک جدول مجازی در دسترس قرار می‌گیرد. در تعریف معمول View، خود داده‌ها به‌صورت مستقل ذخیره نمی‌شوند؛ بلکه دستور پرس‌وجو ذخیره می‌شود.

از آنجا که View پرس‌وجوی اصلی را نگهداری می‌کند، نتایج آن هنگام استفاده بر اساس وضعیت فعلی داده‌های جدول‌های مبنا به دست می‌آیند. بنابراین تغییرات جدید داده‌ها نیز می‌توانند در نتیجه مشاهده‌شده منعکس شوند.

ساخت View

برای ساخت View از ساختار CREATE VIEW استفاده می‌کنیم. ابتدا نام View را می‌نویسیم، سپس با AS پرس‌وجویی را مشخص می‌کنیم که قرار است ذخیره شود.

CREATE VIEW employee_hire_years AS
SELECT dept_id, year_hired
FROM employees;

اجرای دستور CREATE VIEW، خودِ مجموعه نتایج پرس‌وجو را نمایش نمی‌دهد؛ بلکه View را برای استفاده مجدد ایجاد می‌کند.

تمرین: ساخت View برای نویسندگان کتابخانه

می‌خواهیم پرس‌وجوی نویسندگان یکتا را با نام library_authors ذخیره کنیم و نام ستون خروجی نیز unique_author باشد.

CREATE VIEW library_authors AS
SELECT DISTINCT author AS unique_author
FROM books;

استفاده از View

پس از ایجاد View، می‌توانیم مانند یک جدول معمولی از آن داده بخوانیم؛ کافی است نام View را پس از FROM قرار دهیم:

SELECT *
FROM library_authors;

تفاوت اصلی را به خاطر بسپارید: دستور CREATE VIEW پرس‌وجو را ذخیره و View را ایجاد می‌کند؛ دستور SELECT از View استفاده می‌کند و نتیجه آن را نمایش می‌دهد.

۷. گونه‌های مختلف SQL (SQL Flavors)

SQL در سامانه‌های مختلف پایگاه داده ممکن است با نسخه‌ها یا گونه‌های متفاوتی ارائه شود. بعضی از این محصولات رایگان و متن‌باز هستند و بعضی دیگر نسخه‌های تجاری یا سازمانی نیز دارند. با وجود تفاوت‌ها، بخش عمده‌ای از واژه‌های کلیدی و ساختارهای اصلی SQL میان این گونه‌ها مشترک است.

استانداردهای عمومی SQL توسط سازمان‌های استانداردسازی بین‌المللی و آمریکایی، از جمله ISO و ANSI، تدوین شده‌اند. تفاوت گونه‌های SQL معمولاً از قابلیت‌های افزوده و جزئیاتی ناشی می‌شود که محصولات مختلف در کنار این مبانی مشترک ارائه می‌کنند.

PostgreSQL

یک سامانه مدیریت پایگاه داده رابطه‌ای، رایگان و متن‌باز است. این سامانه ابتدا در دانشگاه کالیفرنیا، برکلی شکل گرفت و پروژه آن با حمایت سازمان پروژه‌های پژوهشی پیشرفته دفاعی آمریکا، DARPA، همراه بود.

SQL Server

سامانه مدیریت پایگاه داده رابطه‌ای شرکت مایکروسافت است که نسخه‌های رایگان و سازمانی دارد و با دیگر محصولات مایکروسافت سازگاری و هم‌افزایی خوبی دارد. گونه اختصاصی SQL مورد استفاده آن T-SQL نام دارد.

نام PostgreSQL هم برای اشاره به سامانه پایگاه داده و هم برای اشاره به گونه SQL مورد استفاده در آن به کار می‌رود. در مقابل، T-SQL گونه اختصاصی مایکروسافت برای کار با SQL Server است.

مقایسه LIMIT در PostgreSQL و TOP در SQL Server

یکی از تفاوت‌های ساده میان این دو گونه، روش محدودکردن تعداد ردیف‌های خروجی است. در PostgreSQL از LIMIT استفاده می‌کنیم؛ اما در SQL Server می‌توانیم از TOP پس از SELECT استفاده کنیم.

PostgreSQL

SELECT name, id
FROM employees
LIMIT 2;

SQL Server

SELECT TOP(2) name, id
FROM employees;

در این دو نمونه، هدف یکسان است: انتخاب نام و شناسه کارکنان و محدودکردن خروجی به دو ردیف. تفاوت موردنظر در این مثال، واژه‌ای است که برای محدودکردن تعداد نتایج به کار می‌رود.

محدودکردن تعداد ردیف‌ها هنگام آزمایش و بررسی کد مفید است؛ زیرا ممکن است یک پرس‌وجو هزاران ردیف برگرداند. با این حال، اگر ترتیب مشخصی برای انتخاب ردیف‌ها لازم باشد، باید آن را جداگانه تعیین کنیم؛ صرف استفاده از LIMIT یا TOP ترتیب دلخواهی را تضمین نمی‌کند.

کدام گونه SQL را یاد بگیریم؟

اگر محل کار یا سازمانی که قصد همکاری با آن را دارید از سامانه مشخصی مانند Microsoft SQL Server استفاده می‌کند، یادگیری همان گونه انتخاب روشنی است. اگر هنوز نمی‌دانید در آینده با کدام ابزار کار خواهید کرد، لازم نیست در شروع بیش از اندازه نگران انتخاب باشید؛ زیرا مبانی و بسیاری از واژه‌های کلیدی مشترک‌اند و سازگاری با گونه دیگر معمولاً با یادگیری چند تفاوت قابل انجام است.

تسلط بر مفاهیم پایه مانند انتخاب ستون‌ها، تعیین جدول، نام مستعار و مقادیر یکتا، مهارتی قابل انتقال میان گونه‌های مختلف SQL ایجاد می‌کند.

۸. محدودکردن تعداد نتایج

هنگام بررسی یک جدول بزرگ، ممکن است نخواهیم تمام ردیف‌ها را در هر بار اجرای پرس‌وجو دریافت کنیم. محدودکردن تعداد نتایج کمک می‌کند ابتدا نمونه کوچکی از داده‌ها را ببینیم و کد خود را آزمایش کنیم.

در PostgreSQL از واژه کلیدی LIMIT برای تعیین حداکثر تعداد ردیف‌های خروجی استفاده می‌شود. برای مثال، دستور زیر حداکثر ۱۰ مقدار از ستون genre جدول books را برمی‌گرداند:

SELECT genre
FROM books
LIMIT 10;

در این پرس‌وجو، SELECT genre ستون موردنظر را تعیین می‌کند، FROM books جدول منبع را مشخص می‌کند و LIMIT 10 تعداد ردیف‌های خروجی را به حداکثر ۱۰ محدود می‌سازد.

تبدیل پرس‌وجو از PostgreSQL به SQL Server

اگر بخواهیم پرس‌وجوی بالا را برای SQL Server بنویسیم، باید LIMIT 10 را حذف کنیم و TOP(10) را بلافاصله پس از SELECT قرار دهیم:

SELECT TOP(10) genre
FROM books;

۹. جمع‌بندی جلسه

🧠

مهم‌ترین نکات این جلسه

  • SELECT ستون‌های موردنیاز را انتخاب می‌کند و FROM جدول منبع را مشخص می‌کند.
  • برای انتخاب چند ستون، نام آن‌ها را با کاما جدا می‌کنیم؛ برای انتخاب همه ستون‌ها از * استفاده می‌شود.
  • AS نام مستعار ستون را در خروجی تعیین می‌کند، بدون آنکه نام واقعی فیلد در جدول تغییر کند.
  • DISTINCT مقدارهای تکراری را حذف می‌کند؛ در انتخاب چند ستون، ترکیب کامل مقادیر یکتا می‌شود.
  • View پرس‌وجویی ذخیره‌شده است که مانند یک جدول مجازی می‌توان از آن داده خواند.
  • PostgreSQL و SQL Server در مبانی مشترک‌اند، اما در برخی واژه‌ها و قابلیت‌ها تفاوت دارند.
  • برای محدودکردن تعداد نتایج، در PostgreSQL از LIMIT و در SQL Server از TOP استفاده می‌کنیم.

اکنون می‌توانیم پرس‌وجوهای ساده بنویسیم، ستون‌های موردنیاز را انتخاب کنیم، خروجی را مرتب‌تر و بدون تکرار بسازیم و پرس‌وجوهای پرکاربرد را در قالب View ذخیره کنیم. این مفاهیم پایه‌ای برای یادگیری دستورهای پیشرفته‌تر SQL هستند.
